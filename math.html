The frozen intervention

A fresh exploratory edit multiplies 48 MLP output columns in zero-based transformer block 20 by 0.8. The stored BF16 source audit found 49,152 changed values and 487 other tensors unchanged. The q4f16_1 deployment audit found 73,046 changed decoded values: 49,206 lie outside the exact source coordinates because quantization shares scales within groups of 32, and none lie outside affected source groups. There are 39,114 changed 4-bit values and 1,903 changed scales; 433 other deployed tensors are unchanged.

Scoring and interpretation

Math-Verify 0.9.0 grades final-answer equivalence using the last balanced boxed answer, plain reasoning mode, strict equivalence, and no string fallback. A valid boxed answer in a truncated response can pass. Before target inference, a preflight found eight valid references rejected by the earlier strict LaTeX normalization. The frozen standard_latex option enables malformed_operators and nits identically for references and predictions; no final item or answer was excluded or rewritten. The paper accepts additional box forms and uses different parser defaults. This is a documented local grading policy, and it does not verify the reasoning or proof.

  • One final session per arm, in pristine-then-candidate order. The paired interval describes variation across problems; it does not measure repeated-run resource uncertainty.
  • Final MATH-500 prompts were withheld during this editor session. Prior exposure and training-data independence are not established.
  • The model, architecture and dense computation graph are unchanged. Fewer output tokens do not establish reduced per-token compute, memory or energy.
  • All 500 scheduled problems remain in each accuracy denominator. Truncated and incorrect responses remain in resource totals. A correct boxed answer in a truncated response can still receive credit.
  • This is a browser benchmark extension, not a numerical reproduction of the paper. We use one greedy sample, thinking disabled, q4f16_1 WebGPU and a 1,024-output-position ceiling (up to 1,020 sampled tokens). The paper uses BF16 vLLM, thinking enabled, temperature 0.6, top-p 0.95, top-k 20, presence penalty 1.5, up to 32,768 new tokens and four samples per problem with averaged correctness.
  • The 70 practice problems are balanced across seven subjects and five difficulty levels. They come from MATH training data and are disjoint under the recorded identity, normalized-text, source-row and template-family checks; this does not prove semantic uniqueness or freedom from pretraining contamination.
  • The likelihood selection endpoint was adapted after the initial trace assay. Small selected proxy gains and the seven-item confirmation are development evidence, not an independent estimate of MATH-500 accuracy.
  • The requested editor selector was gpt-6-astra. Provider-side model version and service tier were not independently authenticated. The notebook was reviewed and its kernel shutdown verified, but perfect outer-editor access isolation is not established.
  • Published rows support independent recomputation of correctness counts, paired outcomes, intervals and resource summaries. They omit generated answers and therefore do not enable independent answer regrading. The new runtime source has no confirmed public immutable commit yet.
  • Recovery uses all retained worker allocation samples. The original profile combined main-page and worker samples under a 10,000-point cap; lost main-page samples and that cap interaction cannot be reconstructed. This is a qualified re-analysis, not a byte-exact copy of the original combined profile.
  • The declared host, Chrome binary and settings were frozen and verified. The recovered observed environment contains only the retained user agent; navigator platform and hardwareConcurrency are unavailable. The original supervisor memory/deployment acceptance flags remain false as runner-failure flags; they do not establish a measured memory breach or certify recovered physical-memory acceptance.
