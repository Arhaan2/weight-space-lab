# Later operational profile-cache maintenance

This addendum was introduced after the five existing artifacts completed their fresh quality sessions. It was not part of the original frozen experimental protocol. The scientific controller, source freeze, order, generation settings, model artifacts, original deadline and all finite limits remain unchanged.

A completed dedicated Chrome profile retains approximately 431 MB of local-origin IndexedDB blob cache. Retaining eighteen such caches would consume disk space needed to preserve the study's free-space floor. The separate `scripts/maintain_fresh_profiles.py` helper may delete only `Default/IndexedDB/http_127.0.0.1_4198.indexeddb.blob` inside a completed session's own profile. No active profile or unrelated browser data is eligible.

Before removal, the helper requires the existing session and study bindings, completed supervisor status, every recorded owned-process cleanup flag, no retained owned PID, and a fresh process check showing no owner of that exact profile. It rejects symlinks, path escape, special files, shared hard links, frozen references into the cache leaf, changed evidence, and repeated failed maintenance. All non-profile scientific files, profile `Last Version`, `Local State` and IndexedDB leveldb metadata are hashed before and after. The session’s intentional benchmark symlink is separately checked against the frozen benchmark target and its literal link value is hashed. Unrelated Chrome singleton/version links are left untouched and never traversed. Model source/deployment files, dependencies, reports, generated outputs and grading artifacts are retained.

A separate private maintenance ledger binds the helper and this addendum before the first deletion or helper-driven dispatch. Each maintenance operation uses the unchanged controller's durable action reservation and completion accounting. Receipt and sidecar finalization have a separately bounded, conservatively charged two-second allowance; sidecar construction is also a charged action. Failures stop the study; no target attempt is repeated. The helper's `run-rest` calls the unchanged `run_one` and `export` in the existing remaining order and removes eligible cache payloads between completed sessions while holding the existing root lock.

The sanitized `maintenance.json` sidecar records the late decision, source hashes, per-session deletion counts and bytes, preserved-evidence hashes, failures and charged time. It supplements the canonical scientific result without rewriting its schema. Removing a terminated profile's disk cache does not establish cold operating-system caches, constant host conditions, or a causal resource benefit.
