# Fresh baseline and fourth Astra edit

This is a newly authorized experiment, separate from the closed V1, V2 and five-artifact resource studies. It does not reuse their budgets or mutate their observations. The user requests a fresh baseline, a further Astra edit aimed at higher benchmark compliance, matched resource measurement, and publication of every version.

## Frozen question and cohort

Compare six deployed artifacts: pristine, historical V1, Astra rounds 1–3, and one new independent Astra round 4. Rerun the first five artifacts in that order on the same 32 previously exposed IFEval development prompts. Supply the resulting fresh outputs, independent grades, token counts and allowed weight information to one fresh-context `gpt-6-astra` collaboration agent. Then validate, build, convert and evaluate its one proposal on the same 32 prompts. There are no untouched final prompts and no new generalization claim.

The new proposal starts from pristine. It contains exactly two `scale_columns` operations, one each on layers 15 and 19 `mlp.down_proj.weight` (1,024 × 3,584 BF16): 60 contiguous columns with starts 0–3524 and independent factors from {0.5, 0.75, 1.25, 1.5}. There are 122,880 targeted source coordinates. The existing proposal validator, direct BF16 rounding, independent checkpoint audit, converter, effective quantization audit and package checks are unchanged. No weight optimization or target-model probe is delegated to the editor. Technical editor isolation, immutable provider version, accepted effort, provider tokens and billing remain unverified/unavailable.

The primary objective is higher strict prompt compliance. Report whether round 4 exceeds (a) fresh pristine and (b) the best fresh prior artifact separately. At most the fresh baseline's scored output-token count is a secondary efficiency target. It is not a gate that hides a valid candidate or prevents resource measurement. Output-token counts alone are not compute, memory or energy measurements. There is no promise that a new edit will improve the score.

The exact four-key response JSON remains unchanged. Astra supplies a separate rationale of at most 150 words; it is saved and hashed with the proposal before building or evaluating the new candidate. This is the editor's pre-evaluation hypothesis, not a post-hoc explanation or evidence of causal neuron semantics. The complete indexed packet, every delivered part and their concatenation are frozen before the single editor turn.

Quality generation and the unmodified official grader retain the pinned 32 tasks, temperature 0, top-p 1, seed 42, thinking disabled, context 4096, output cap 1024 positions, one 16-position warm-up, fresh conversation per request, 120-second request ceiling and no retries. Four injected boundary IDs are excluded from sampled output-token counts. The official IFEval grader has a 20-second per-item ceiling, no retry, and grades truncated output. All six runs use the newly frozen current browser/device identity. One quality run per artifact is adaptive development evidence, not an independent replication.

## Resource phase

After all six quality sessions and technical checks complete, freeze the six actual deployment identities. Every technically valid artifact is included regardless of its score. The resource order is:

`pristine → v1 → v2-r1 → v2-r2 → v2-r3 → astra-r4 → astra-r4 → v2-r3 → v2-r2 → v2-r1 → v1 → pristine`

Each session uses Browser LLM Bench's existing standard repeated-prompt workload: 60 measured requests in three windows of 20, with 90-second gaps, 15-second baseline, 30-second final loaded idle, 15-second recovery, one warm-up, 64 output positions, 60-second request ceiling, and the same decoding/runtime controls. The public prompt is “In three short sentences, explain why leaves change color in autumn.” It is not an IFEval quality task. Each session gets a fresh dedicated Chrome profile and empty IndexedDB; OS filesystem caches are not cleared. No UI-preview browser runs concurrently.

The replication unit is the browser session. Publish both observations and their arithmetic mean/minimum/maximum, retaining every scheduled position and failure. Artifact throughput is the equal-weight mean of session token/response-time ratios, not pooled throughput. Missing/incomplete pairs produce unavailable means; missing telemetry is null, never zero. Matched-resource deltas require matching observed browser/device identities and runtime/quantization/library identity across all 12 sessions. Mirrored order balances linear ordinal drift, not arbitrary thermal, background or elapsed-time effects. Two sessions on one device do not establish significance or equivalence.

Native footprint is the sampled sum of accounted process-tree footprints, not globally deduplicated physical RAM or model-only memory. GPUBuffer descriptors and WASM address space are allocation bookkeeping, not physical VRAM. CPU capacity and experimental GPU milliseconds per second are activity rates, not total computation. Power may be unavailable; no energy value is invented. The website must display duration alongside activity and memory observations and keep this cohort separate from historical measurements.

## Limits, staging and accounting

The new maximum is 18 loads, 18 warm-ups, 192 quality requests, 720 resource requests, 930 total dispatches and 242,976 reserved output positions. There is one editor proposal, one response import, one source build, one conversion and one package. Browser time is capped at 180 minutes, total local charged time at 240 minutes, and calendar time at 24 hours from the initial study freeze. Retained logical data is capped at 32 GiB; at least 8 GiB must remain free, including explicit per-build storage reserves. Host memory pressure ≥4, thermal state ≥2, or unknown required host signals stops execution. Automatic generation, grader, proposal and conversion retries are zero.

Every target session and editor/build action is durably reserved before dispatch. A reservation, invalid response, failed preparation, or interrupted action is never silently reset. Failed and unresolved attempts remain visible, with actual versus reserved capacity distinguished. An exact retry-free resumption may execute only still-pending positions after completed predecessors; an active or halted state refuses automatic continuation. Cleanup must confirm the browser, worker, local harness/controller and owned processes exited. Resource capture must also confirm its own exit.

Before the first target dispatch, stage and hash the complete browser source/build and npm dependencies, exact model payloads, official evaluator and tokenizer data, pinned cached Python wheels, pristine BF16 source, and pinned converter dependencies away from Desktop file offloading. This staging changes no installed environment or historical file. Cached bytes are accepted only under their exact identities; no downloaded upgrade or substitute payload is allowed. A clean source checkout supplies all execution code. Candidate conversion readiness and its storage peak are checked before spending the five fresh quality sessions. Preparation, integrity verification, failures, grading, reporting and candidate actions are charged to the new local budget; browser stages additionally consume browser time. All immutable inputs and actual source files are frozen before first load. The single future candidate is bound separately without rewriting the parent study identity.

The new converter environment preserves the pinned package versions and quantization-mapping code. Its private macOS library copies may receive new ad-hoc signatures required for loading: unsigned payload identity and non-signature code/data bytes are verified, and each resulting signed file is frozen separately. New signatures are not described as byte-identical to the old installed signatures. The converter's 435-parameter WASM metadata is derived directly from the exact hash-verified compiled library when the historical metadata JSON is unavailable; full byte identity with that old JSON is not asserted. The staging receipt records these transformations and the successful no-inference converter preflight. The complete pristine 11-file source retains its exact original manifest identity.
